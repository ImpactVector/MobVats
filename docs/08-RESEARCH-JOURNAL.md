# 08 — Procedural research journal proof of concept

This is a local development prototype for Minecraft 1.21.1 / NeoForge 21.1.252.
It adds `mobvats:research_journal` to the MobVats creative tab and generated
manual-world Vat supply chests. Existing saved worlds are not reset or edited.
Use `/give @s mobvats:research_journal` in an existing testing world. Right-click
to open; arrow buttons, arrow keys, and Page Up/Down move between four spreads.
Escape closes the book. Notes are placeholders and establish no permanent lore.

## Source investigation and incorporation

This is a selective source adaptation of the page architecture, not a binary
API-compatible Modonomicon fork. It does not retain book trees, unlock filtering,
server book synchronization, bookmarks, search, fluid recipes, Markdown, or JEI.
No mandatory Modonomicon dependency, foreign-mod mixin, shader, or new library is
added. Direct extraction of the complete screen/data stack would import those
unneeded systems. A larger documentation framework should be a separate decision.

## Geometry and rendering

All values below are Minecraft logical GUI pixels. Vanilla GUI scaling applies;
the book does not take over window resolution or input devices.

| Geometry | Bounds |
| --- | --- |
| Full binding/stack | 272 × 178 |
| Left physical paper | x=8, y=6, width=128, height=166 |
| Right physical paper | x=137, y=6, width=128, height=166 |
| Upstream nominal content | x=12/141, y=15, width=124, height=155 |
| PoC actual text clip | nominal x+2..118, y..146 |
| Protected area within each physical paper | x=6..122, y=9..155 (right/bottom exclusive) |
| Composite resolution | 256 × 332 (2× physical paper) |

The physical bounds are an explicit prototype geometry decision for the new
binding, not a claim that upstream's atlas has precisely the same paper outline.
Text and recipes use a slightly narrower safe area than upstream's maximum.
The protected rectangle is horizontally symmetric, so reflected leaf masks also
protect verso content. Title/body overflow is rejected when preparing a page;
the screen additionally clips content to the safe area.

Draw order: binding/underlying stack; left and right composites; left and right
content; controls; tooltips. A hole reveals the stack, not another stain painted
over an absent sheet. Page-type renderers never choose paper or damage.

CPU composition copies/resamples the selected paper; paints physical crease/wear
decals, surface stains and authored decorations; then subtracts physical mask
alpha while preserving the base paper silhouette. White mask pixels with alpha 255 remove paper completely. Mask RGB is
ignored; transparent pixels preserve paper. Stains inside the protected region
are attenuated to 18% opacity for technical readability. Masks cannot alter the
protected region. Mask prototypes use opaque cutouts; visible decals use colored
RGBA with transparent backgrounds. Wear is shared leaf-level; burns are visible
surface charring, while mask assets provide removed/burnt-away paper.

## Determinism and physical order

Algorithm version 1 uses FNV-1a-64: initial offset `0xcbf29ce484222325`, prime
`0x100000001b3`, seed as eight little-endian bytes, then each UTF-8 string prefixed
with its four-byte little-endian byte length. Java long arithmetic wraps at 64
bits. Independent streams use SplitMix64 with increment `0x9e3779b97f4a7c15`,
mix multipliers `0xbf58476d1ce4e5b9` / `0x94d049bb133111eb`; doubles use the top
53 bits divided by 2^53. Sorted asset IDs define weighted selection order.

Surface seed = hash(journal seed, entry ID, anchor, decimal seed offset).
Each category and paper selection hashes that seed with its category string.
Leaf stream = hash(journal seed, "leaf", leaf ID, category, preview offset).
Normal preview offset is zero. The page seed offset rerolls surface/paper only:
it cannot break the shared leaf geometry. No item NBT, player ID, world seed,
wall clock, networking, Java String.hashCode or navigation index enters a seed.

Canonical order is the book's ordered entry list and each entry's page array,
before any future unlock filtering. Anchors must be nonblank and unique within
an entry; leaf surfaces are unique and leaves must be consecutive, recto before
verso. The demo starts with leaf_a verso and ends with leaf_e recto, with three
complete leaves between. Thus the two surfaces of leaf_d are page 6 (recto) and
page 7 (verso), on opposite sides of a page turn. Page 5/6 is not a single leaf.

Both sides use the highest-severity physical rule across that leaf's surfaces
(canonical first surface wins ties). Leaf damage is generated once conceptually
in canonical coordinates; verso projects x→1−x, rotation→−rotation and toggles
reflection. Surface stains remain local. Profile changes on either side can
therefore change the shared leaf; unrelated page insertion cannot reroll it.

The authored `prototype_spill` starts at leaf_d and penetrates leaf_e. Intensity
is `initial × falloff^leafDistance`, with zero before origin and at/after depth.
Both sides of a leaf have equal penetration intensity and reflected projection;
this event does not use page RNG. Inserting a new intervening leaf deliberately
changes regional penetration distances, while local procedural appearance stays
stable.

## Resource schema

Resources are client resource-pack data under `assets/mobvats/journal/`.
Filenames relative to the following directories are stable IDs. The PoC reads
the MobVats namespace; external packs can override or add files there.

* `book.json`: fixed long `seed`, ordered `entries` resource IDs, `events` array.
* `entries/<id>.json`: nonblank `id`, inherited `profile`, ordered `pages`.
* `profiles/<id>.json`: optional `extends`, `paper` weight map and `damage` rule map.
* `texture_library/<id>.json`: one asset definition per file.

Profiles recursively merge objects, including category rule patches. Inheritance
cycles and missing parents fail validation. Array overrides replace entire arrays.
The four shipped profiles are pristine, experimental, obsessive and deranged.
Each category has `enabled`, `probability` (0..1), inclusive `min`/`max` decal
counts (0..32), `scale` [min,max], `opacity` [min,max], `rotation` (`"free"` or
nonempty degree array), `mirror`, `placement` (`anywhere`, `edge`, or
`outside_content`), and `severity` (0..1). A probability roll precedes the count
roll, so even a severe profile can produce a comparatively clean surface.

Asset example:

```json
{
  "texture": "mobvats:textures/gui/journal/damage/blood/blood_1.png",
  "category": "blood",
  "weight": 1,
  "placement": "anywhere",
  "scale": [0.7, 1.2],
  "opacity": [0.65, 1],
  "rotation": "free",
  "mirror": true,
  "minimum_severity": 0
}
```

The file's ID, not a mutable list index, identifies the asset. Texture locations
include `textures/` and `.png`. Categories are `paper`, `masks`, `blood`,
`chemical`, `ink`, `burns`, `wear`; additional visible categories work if a
profile defines them. `paper` selection uses profile weights. Category selection
uses asset weights and minimum severity. Asset and rule scale/opacity ranges
multiply. A finite asset rotation array takes priority over the rule rotation;
both sides must permit reflection. A restrictive asset placement takes priority
over rule placement. Edge/outside-content restrictions place decal centers at
the outer edge; large decals can extend inward and are attenuated over content.
Paper prototypes are 256×332 and decals 80×80 with consistent 2× texel density.

Page example:

```json
{
  "anchor": "experiment_042",
  "leaf": "leaf_d",
  "verso": true,
  "type": "text",
  "title": {"text": "Trial notes", "bold": true},
  "text": [{"text": "Observation. ", "italic": true}, {"text": "Repeat."}],
  "appearance": {
    "profile": "obsessive",
    "seed_offset": 7,
    "damage": {"blood": {"probability": 1}, "burns": {"enabled": false}},
    "decorations": [
      {"asset": "ink_2", "x": 0.91, "y": 0.14, "scale": 0.65,
       "rotation": 18, "opacity": 0.8, "mirror": false}
    ]
  }
}
```

`appearance` is optional. Formatted text accepts a literal string or Minecraft
component JSON. A crafting page uses `"type":"crafting"` and a recipe ID such
as `"recipe":"minecraft:crafting_table"`. It resolves the connected level's
real recipe manager, supports shaped and shapeless crafting, renders actual
ingredients/results with item tooltips, and shows an unavailable message if
the recipe is absent. The PoC selects the first valid ingredient alternative;
it does not cycle substitutions or integrate recipe transfer.

Authored decorations use normalized paper coordinates, degrees, scale relative
to source PNG size, opacity 0..1 and optional reflection. They remain a separate
layout list, do not consume procedural RNG, and are still clipped by final
physical masks. Narrative marginalia must be authored, never synthesized by RNG.

Events define `id`, `origin_leaf`, `category`, `asset`, normalized `x`/`y`,
`scale`, degree `rotation`, `intensity` 0..1, positive leaf `depth`, and `falloff`
0..1. The selected texture must match the category. Events are sorted by ID for
stable paint order.

## Preparation, resource reload and ownership

`JournalDecorationGenerator`, `JournalPageCompositor`, `JournalData` and
`JournalCache` have no Minecraft client or OpenGL dependency. The compositor
works on ARGB arrays; the client adapter explicitly converts to/from NativeImage
ABGR. Decoded source NativeImages close immediately after conversion. A generated
NativeImage transfers to DynamicTexture; TextureManager.release owns its GPU
and native disposal. Exceptional uploads close their temporary owner.

Pages are prepared on begin-display/navigation, resize, preview changes, or the
tick following resource reload. Render only draws registered textures: no
per-frame layout generation, pixel composition or upload. An access-ordered LRU
owns at most 16 composites (~5.2 MiB pixel storage each on CPU/GPU in total) and
48 decoded source arrays, individually limited to 1024×1024. Evictions release
textures; screen close and resource reload clear both caches. Minecraft's texture
manager also closes registered textures at client shutdown. Cache keys include
page identity, preview seed/offset/profile/layer and disabled categories.

Reload clears caches and increments a revision. Data parsing validates into a
new model before replacing the last valid one. Invalid reload data logs an error
and retains the previous model. Initial malformed data has no fallback book and
reports a load failure. Missing/malformed image files log once per resource and
reload, then become opaque neutral paper or transparent decals/masks. Thus a
missing mask never removes arbitrary content and a missing paper stays readable.

## Developer preview and validation

Development clients provide `/mobvats_journal_preview`. Normal production clients
do not register it. Preview state belongs only to that screen and never changes
the regular journal seed or saved data.

| Key | Preview action |
| --- | --- |
| P | Cycle authored profiles / forced profile |
| S / Shift+S | Increment/decrement journal seed |
| R | Increment preview offset (reroll); displayed in header |
| L | Cycle all / paper / surface / physical / authored layers |
| 1..6 | Toggle blood / chemical / ink / burns / masks / wear |
| Arrow keys, Page Up/Down | Navigate test spreads |
| Hover bottom margin | Inspect entry/anchor, leaf ID and recto/verso |

Each isolated layer mode retains base paper for comparison. Physical mode shows
wear and removed paper; surface mode includes correlated events. Normal mode
combines all layers in the documented order. Preview controls intentionally use
keys to keep the 272×178 book usable at ordinary GUI scales.

The canonical Java 21 `validate` mode runs formatting checks, build, CPU checks,
and autonomous headless GameTests. `journalTest` is attached to `check`. It checks
repeatable layouts/pixels, independent category streams, unrelated insertion,
anchor rejection, inheritance/overrides, asset/rule rejection, full-resolution
reflected alpha masks, protected content, clipped stains, penetration bounds,
fallback pixels, bounded eviction and reload disposal. It exports a 128-case
seed/profile survey to `build/reports/journal/seed-survey.png`. The server test
verifies registration and a survival-player interaction without item mutation.

Validated November 25, 2026 with the canonical Java 21 launcher: formatting and
build passed; all 1,182 required headless GameTests passed. A subsequent CPU-only
transparent-paper clipping fix passed the final build and 157,352 journal
assertions across the 128-case survey. The development JAR contains all 21 PNGs,
20 asset definitions, journal data/item/screen and the upstream permission notice.
Existing concurrent CPU render tests emitted Log4j rollover contention messages
but completed successfully. No client visual or GPU-memory acceptance is claimed.

Client visual acceptance remains with the user under workspace instructions.
No Minecraft client smoke, reload, screenshot loop or manual automation is run.
Before declaring the client acceptance criteria complete, verify all four spreads,
recipe tooltips/readability, repeated navigation/close/reopen, restart identity,
GUI scales, mirrored page 6/7 tears, spill falloff, F3+T resource reload, and GPU
cleanup/memory stability over repeated opens and preview rerolls.

## Production recommendations and limitations

Keep algorithm version 1 stable or version the authored format before changing
hashing, selection ordering, palettes or asset weights. Asset-library changes can
intentionally change weighted selections within that category. Freeze the library
for published chapter appearances when stronger art stability is required.

The CPU survey does not establish client rendering, tooltip ordering, GPU lifetime
or final visual acceptance. The debug screen exposes controls, not an inspector
for arbitrary external books. No production content, research tree, Markdown,
clickable text links, illustrations, machine page types, page unlocks, animated
art, or production binding is supplied. Add those through typed renderers and
resource schema changes rather than coupling them to paper decoration.

Production work should add font-aware reload validation with recoverable overflow
errors, accessibility/narration/localization of controls, more intentional tear
shapes, authored physical-damage events and leaf overrides, finer layer inspection,
resource size budgets before image decode, and measured client allocation tests.
The protected region intentionally confines destructive damage to narrow edges;
readability takes precedence over cutting into technical diagrams.
