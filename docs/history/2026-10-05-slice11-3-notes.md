MobVats Slice 11.3 - Boundary Devices and Sump cleanup

Migration and removal
---------------------
The specimen collection endpoint is now Vat Sump / VatSumpEntity / VatPartType.Sump.
Its block, item and block-entity registry identifier remains mobvats:vat_drain.
Existing placement, saved serviceStaging, specimen geometry and association rules
are unchanged. The existing internal MobAssembly.drain() accessor and serialized
mobvats:drain actor-use identifier remain compatibility names. User-facing names,
support tooltips and validation messages say Sump. No registry remapping of the
specimen endpoint is needed and one Sump is still required per specimen.

Sewer has no registered block/entity/item entry, recipe, model, language entry,
topology role or actor. Old mobvats:vat_sewer block, block-entity and item IDs alias
mobvats:vat_casing. Old placed Sewers therefore become ordinary Vat Casing; old
Sewer items become Casing items. The alias is not a Creative entry. An old
interior Sewer consequently becomes an interior Casing, which is structurally
invalid: remove that Casing to restore assembly. Sumps remain in place and keep
their associations. Passive Waste production no longer needs an auxiliary actor.
Tests verify the aliases and absence of a Sewer registry entry; an imported
historical world was not manually opened.

Boundary operations
-------------------
Pull and Push Pumps are separate craft-switched variants sharing a boundary entity.
They form only on shell faces, excluding frames, edges and interior positions.
World interaction is directly outward. Direct Buffer or TAP connections attach
only on the inward side. Operations run every ten server ticks and retain no
bulk fluid. No world mode toggle exists.

Pull transfers exactly 1000 mB from an adjacent LiquidBlock source after full
destination simulation. Insufficient capacity or filter mismatch leaves the
world and storage untouched. A finite source is removed after the fluid commit.
Vanilla water-source regeneration is recognized only when water conversion is
enabled, two horizontal water sources neighbor the root, and its support below
would allow regeneration. In that case the source remains and produces 1000 mB.
No large-body bottomless detection is implemented.

Push uses only fluids whose source state produces a LiquidBlock. Container-only
fluids such as milk are reported unsupported without consumption. Placement
requires exactly 1000 mB, an accessible root and loaded, replaceable cells.
Traversal crosses empty space and fluid of the selected type, never solid blocks,
block entities or different fluids. Choice order is lowest Y, root distance,
then X/Z position. Lower levels fill outward before the next level rises.
Existing sources can be traversed but never overwritten or charged again.
The search never rises above the root, reaches at most 16 blocks horizontally
and downward, and refuses searches exceeding 4096 visited cells. Water placement
in ultra-warm dimensions is rejected. Waterlogged blocks are not pump sources.

Fill Valve accepts shell faces or interior positions at any height and injects
1000 mB into an available interior medium cell. Water and Culture Slurry are the
supported media, consistent with the existing vat structural medium rules.
Drain Valve forms only on the BottomFace, not side/top/interior-above-bottom.
Drain selects one matching fluid type and evacuates its entire interior source
batch, including residual flowing cells, after full destination preflight. This
requires capacity for that complete batch (or a matching Fluid Void). Otherwise
it waits without modifying the medium. Batch evacuation prevents vanilla source
regeneration from duplicating medium during partial drainage. Each source counts
as 1000 mB; residual flow does not create extra fluid. Neither Valve stores fluid.
Valve blocks count as physical machinery in existing clearance observations.

Bus storage never invokes world or medium operations. Only the explicit boundary
devices cross those domains. Conduits retain resource connectivity and TAP/TRUNK
attachment; they gain no selectors, channels, storage or world interaction.

Filters and crafting
--------------------
Sneak-use while unformed samples an exact fluid from a filled container without
changing that container. Item Void samples an exact item. Empty-hand sneak-use
clears configuration. Formed filters are locked through the interaction path.
Filters serialize in block data and portable endpoint item/drop data. Pump
shapeless conversions preserve the exact-fluid filter. Item/Fluid Void shapeless
conversions clear the selector because item and fluid IDs belong to different
registries. Fill and Drain Valves are separate recipes, not reversible modes.

Disposal priority and rendering
------------------------------
Item results offer normal connected Item Outputs first; only the remainder may
reach a matching Item Void. This covers Tool-local results and passive Sump items
such as eggs. Filtering remains on endpoints. Tool backlog behavior is unchanged
when no matching Void exists. Exported-item and voided-item metrics are separate.

Fluid input and service evacuation offer compatible real tanks first, then a
connected matching Fluid Void. New fixed resource-process output planning also
uses Void only after compatible storage/staging has no remaining capacity.
An unfiltered Void accepts the remaining resources in its own category. A Waste
Void does not consume Experience. Simulation does not pulse or store resources.
Void has no retained inventory or tank. Removed sinks cannot accept resources.

Both variants have a recessed lava chamber. Item uses an iron shell; Fluid uses
a copper shell. Committed disposal synchronizes an eight-tick surface flare.
Idle diagnostics return to Idle when the flare expires. No fake item sprites,
dropped entities or continuous extra particle animation are added. Assets use
vanilla Minecraft materials; client visual acceptance remains manual.
