MobVats Slice 12.1 - Vat environment and specimen productivity

IMPLEMENTED CONTRACT

Productivity has two independent axes. Culture frequency scales biological timers;
happiness scales native specimen output amounts. Default ranges are 0.5..5x frequency
and 0.5..2x yield. Feed, routing, tools, obstruction and storage remain eligibility
conditions. No quality stat, fake Looting or faster Tool Port actuator was added.

VatMediumStorage belongs to the controller and persists the complete FluidStack.
It is separate from Fluid Buffers and service staging. Stored culture in a Fluid
Buffer never buys speed or moves into the environment without a Fill Valve.
Old cultureCredit/cultureCreditsByCost fields are ignored; no paid-budget state is
written. Legacy culture_slurry definition fields remain readable but are inert.

Interior volume is 1000 mB per geometric cell minus numeric displacement. Shell
cells contribute nothing. VatDisplacement.Provider and registered lookup functions
return 0..1000 mB; FluidBufferBlock supplies 1000 and the ordinary fallback is zero.
Capacity does not depend on a special Fluid Buffer branch in the volume algorithm.
Each Y-level fills uniformly from the bottom. Cell exposure is available volume
fraction times the level fill fraction. Stored excess is preserved and reported;
exposure uses only realizable capacity. Fill refuses overfull input; Drain can
recover it. Reconnection conflicts are retained separately and drained sequentially,
with no blending or productivity from the inactive conflicting contents.

Fill Valve accepts filtered network contents at any legal shell/interior height.
Drain Valve remains bottom-plane only. Both preserve every component and transfer
up to 1000 mB per cadence, including partial tails. Pumps retain their explicit
world-fluid behavior and intentionally lossy compound-family spills.

When empty, the controller captures homogeneous legacy interior source cells at
1000 mB each before removing world fluid. Water is recovered exactly. Compound
families retain their already-unknown formula; no composition is invented. Mixed
source identities retain their blocks and emit a deterministic diagnostic until
corrected. The persisted migration marker prevents repeated capture after draining.

CONFIGURATION

Server culture data lives in config/mobvats/culture/. _defaults.json is copied from
bundled culture_defaults.json only if absent. Later filename-sorted JSON files are
complete replacement configurations, validated before publication. Invalid files
are logged and leave the last valid configuration active. The existing command
/mobvats reload_passive_mobs also reloads culture data.

../examples/CULTURE_PROFILES.example.json demonstrates the schema:
  profiles: map of names to ordered medium rules (first match wins)
  mobs: specific entity ID -> profile assignment
  groups: ordered [{mobs: [entity IDs], profile: name}] assignments
  default: fallback profile name for unassigned entities, including modded mobs
  rule: {medium: exact/tag/native fluid ingredient, required: composition, frequency}

Specific assignments precede groups, then default, then the generic 0.5x fallback.
Assignments never depend on the entity's spawn dimension. Default dimensional
conventions and mob exceptions exist in JSON only. Unknown family-only cultures
cannot satisfy an enriched composition rule. Required entries use minimum formula
amounts and allow extra additives. Canonical identical selectors match directly;
an exact formula resource can satisfy a configured tag/native ingredient selector.
Unknown tag formulas are not expanded into invented exact resources.

The full persisted geometry comfort shell is the normalization denominator. Culture
contribution per cell is 0.5 + exposure*(matchedFrequency-0.5). Happiness uses the
existing SpecimenClearance observations. Physical cells and neighboring bodies
receive zero credit; cosmetic service shapes do not. Otherwise credit is 1 divided
by the number of comfort shells claiming that cell. Yield is 0.5+1.5*creditedFraction.
Minimum legal tanks remain geometry+2 and produce minimum happiness. Larger bodies
require more space/fluid but receive the same ceilings.

RUNTIME AND PERSISTENCE

Growth, accelerated secondary production and sheep recovery use double rates with
persisted fractional progress per timer. Generic ResourceProcess.accelerated is an
explicit opt-in; omitted/false timers retain machine time. Tool attack count, weapon
damage, tool durability, feed and container consumption remain native mechanics.

Kill loot and XP are scaled after the native roll, then frozen in persisted pending
output for retries. Shearing scales the NeoForge native drops. Milk, Waste, Blender
meat and configured secondary outputs scale their native amounts. Generic output
ResourceOutput.yield_scaled is an explicit opt-in; omitted/false keeps resource
transforms unscaled. Default new chicken definitions mark eggs accelerated and
yield_scaled. Existing user/default passive JSON is not overwritten: add these
flags to existing biological resource processes when appropriate.

Per-specimen fractional yield is keyed by operation stream and full item/fluid
identity, or the XP stream. Yield plans are pure until their output transaction
commits; failed plans and rolled-back transactions do not spend carry. Kill carry
commits with the prepared native loot and is not spent again by blocked output
retries. Metrics record actual scaled emissions.

Specimen fluid service allowances accommodate a maximum 2x native operation.
Mixer allowances retain their previous sizing. Capacity persists with each service
tank and its portable endpoint. Manual Tool Port dairy accumulates actual scaled
fluid in the Tool's existing endpoint-owned service staging; filling a bucket still
consumes exactly one bucket and exactly its native fluid amount. No fractional or
duplicated container items are emitted.

VALIDATION

Headless regression suite: 345 required GameTests passing (329 prior tests adapted
for the superseded balance, plus 16 new Slice 12.1 tests). Coverage includes level
filling, numeric displacement, partial/component-preserving valves, mixed identity
rejection, over-capacity recovery, legacy source conflicts and unknown composition,
subset rules, profile precedence, per-resource yield carry and rollback, frequency
carry, minimum geometry, shared reach, size normalization, generic timer opt-in and
actual scaled metrics. Packaged build/resource verification passes. Client play and
visual acceptance remain user-controlled; no Minecraft client was launched.

The supplied handoff ended at the start of section 19. Fractional timing was
implemented with persisted per-timer remainders using the requirements above it.
